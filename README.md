# Wellscore — NAD+ 자가검사 웰니스 서비스 (프로토타입)

DBS(건조혈액반점) 방식으로 진행하는 NAD+ 자가검사 웰니스 서비스의 웹 프론트엔드입니다.
순수 HTML/CSS/JS로만 만들어져 있어 별도 빌드 과정 없이 Cloudflare Pages 등 정적 호스팅에 바로 배포할 수 있습니다.

브랜드명 "Wellscore"는 임시 제안명이에요. "웰니스(Wellness) + 점수(Score)"로, NAD+ 외에 글루타치온 등 다른 웰니스 지표로 확장해도 자연스럽도록 지어봤어요. 정식 출시 전에는 상표/사업자명 중복 여부를 반드시 별도로 확인해주세요 (간단히 검색해본 결과 "웰마커", "웰로그", "마이랩", "Cohort"류 후보들은 이미 비슷한 실존 회사/서비스가 있어서 제외했어요. Wellscore도 제가 한 건 간단한 웹검색 수준이라 법적으로 확실한 건 아니에요).

## 폴더 구조

각 HTML 파일은 CSS와 JS가 전부 파일 안에 내장된 **독립 실행 파일**이에요. 별도 css/js 폴더 없이 파일 하나만 열어도 디자인과 기능이 그대로 동작해요.

```
wellscore-wellness/
├── index.html            홈
├── about-nad.html         NAD+ 및 DBS 검사 상세 소개 (비의료 서비스 안내 포함)
├── store.html             검사 키트(검사권) 구매 (비의료 서비스 안내 포함)
├── checkout.html          결제 — 토스페이먼츠 결제위젯 연동
├── checkout-success.html  결제 성공 시 토스페이먼츠가 돌아오는 페이지
├── checkout-fail.html     결제 실패/취소 시 토스페이먼츠가 돌아오는 페이지
├── signup.html            회원가입 (이름/이메일/연락처/생년월일/성별/배송주소/비밀번호)
├── login.html             로그인 (+ 데모 계정으로 바로 둘러보기 버튼)
├── mypage.html            마이페이지 — 로그인 필요
├── kit-request.html       검사권으로 키트 배송 신청 — 로그인 필요, 가입 주소 자동입력
├── report.html            검사 리포트 (예시 화면) — 동년배 퍼센타일 방식
├── 404.html
└── README.md
```

## 💳 결제: 토스페이먼츠 연동 (중요, 꼭 읽어주세요)

`checkout.html`은 **토스페이먼츠 실제 JS SDK(v2)**를 연동했어요. 토스페이먼츠 공식 문서에 공개되어 있는 테스트용 클라이언트 키(`test_gck_docs_...`)를 사용해서, 실제 상점 가입 없이도 결제위젯 UI가 뜨고 결제 흐름을 테스트해볼 수 있어요. 테스트 키로 진행하는 결제는 **실제로 청구되지 않아요.**

**두 가지 꼭 알아두실 점**

1. **로컬 파일(더블클릭)로 열면 결제위젯이 안 떠요.** 토스페이먼츠는 결제 후 실제 URL(`https://...`)로 되돌아와야 하는데, `file://`로 열면 그 주소를 만들 수 없어요. 그래서 로컬 미리보기에서는 자동으로 이전의 모의 결제 화면(버튼 누르면 바로 완료)으로 대체되도록 만들어뒀어요. **실제 토스 결제창은 Cloudflare Pages 등에 배포한 뒤(https 주소)** 열어야 확인할 수 있어요.
2. **결제 승인(카드사 승인) 단계는 원래 서버가 해야 하는 일이에요.** 토스페이먼츠 결제는 "결제창에서 승인 → successUrl로 돌아옴 → 서버가 시크릿 키로 결제 승인 API를 호출해야 최종 완료" 순서로 진행돼요. 이 서버 쪽 승인 API 호출은 시크릿 키가 필요한데, 시크릿 키는 절대 브라우저(프론트엔드)에 넣으면 안 되는 값이라 지금 이 프로�트(백엔드 없는 정적 사이트) 구조로는 구현할 수 없어요. 그래서 `checkout-success.html`은 "결제창에서 성공 신호가 왔다"는 것만 확인하고 검사권을 지급하도록 되어 있고, 실제 서비스로 전환할 땐 **반드시 백엔드를 만들어서 결제 승인 API(`POST /v1/payments/confirm`)를 호출하는 과정을 추가**해야 해요. 이 부분은 프론트엔드만으로는 원천적으로 대체할 수 없는 부분이라 미리 말씀드려요.
3. 실제 운영 전환 시 `checkout.html`의 `TOSS_CLIENT_KEY` 값을 토스페이먼츠 가입 후 발급받은 내 상점 클라이언트 키로 교체해주세요.

## 비의료 서비스 안내 문구

말씀 주신 문구를 반영해서 아래 지점에 넣었어요.

- 홈(index), NAD+ 검사란(about-nad), 구매하기(store), 리포트(report) 화면 하단 공통 문구
- **NAD+ 검사란** 페이지 상단, **구매하기** 페이지 결제 버튼 아래, **결제하기** 페이지 — 별도 안내 박스로 눈에 띄게 표시
- 리포트 해석 영역에도 동일 문구 포함

## 리포트: 동년배 퍼센타일 방식

"낮음/보통/최적" 같은 건강 상태를 암시하는 표현은 빼고, **"동일한 분석 방법으로 측정한 동년배 그룹 대비 상위/하위 %"** 만 보여줘요 (정규분포 곡선 위에 위치 표시). "진단이 아니다"라는 문구도 명시했어요.

## mypage.html / kit-request.html이 안 열려요

정상이에요 — 로그인이 필요한 페이지라서, 로그인 없이 파일을 바로 열면 login.html로 자동 이동해요. 로그인 페이지의 **"데모 계정으로 둘러보기"** 버튼을 누르면 바로 확인할 수 있어요.

## ⚠️ 이건 프론트엔드 데모예요

실제 서버가 없는 정적 사이트라서, 아래는 브라우저 `localStorage`로 **흉내만 낸 것**이에요.

- **회원가입/로그인**: 비밀번호가 암호화 없이 브라우저에 저장돼요. 실제 서비스에는 백엔드 서버 + DB + 정식 인증이 필요해요.
- **결제**: 위 "토스페이먼츠 연동" 항목 참고 — 서버의 결제 승인 API 호출이 빠져있어요.
- **배송/검사 상태**: 키트 신청 시 상태가 "배송준비중"으로 고정돼요. 실제로는 관리자 페이지나 검사기관 연동으로 상태가 갱신되어야 해요.
- **가입 시 자동 지급되는 검사권 1개 + 완료된 예시 리포트 1건**: 데모 체험용 시드 데이터예요. 실제 운영 시엔 `signup.html` 안의 "데모 체험용 시드 데이터" 주석 부분과, 로그인 페이지의 "데모 계정으로 둘러보기" 버튼을 제거하면 돼요.
- **가격 표시**: "원가 50,000원 → 30,000원(40% 할인)"으로 표시했어요. 이 "원가"가 실제로 과거에 판매했던 가격이 아니라 내부 원가라면, 할인 표시 방식이 전자상거래법상 문제 없는지 확인해보시는 걸 권해드려요.

## 미리보기 (로컬)

각 파일이 독립적이라 `index.html`을 그냥 더블클릭해서 브라우저로 열어도 디자인이 그대로 보여요. 단, 결제 페이지의 실제 토스 위젯은 위에 설명한 이유로 배포 후에만 확인할 수 있어요.

## Cloudflare Pages로 배포하기

### 방법 A. 대시보드에서 드래그 앤 드롭 (가장 쉬움)

1. [Cloudflare 대시보드](https://dash.cloudflare.com) → **Workers & Pages**
2. **Create application → Pages → Use direct upload**
3. 프로젝트 이름 입력 후 **Create project**
4. 폴더(또는 zip) 전체를 드래그 앤 드롭 → **Deploy site**

### 방법 B. Wrangler CLI

```bash
npm install -g wrangler
npx wrangler pages deploy ./wellscore-wellness --project-name=wellscore-wellness
```
